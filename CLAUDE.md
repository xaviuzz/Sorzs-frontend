# Sorzs-frontend

React app on Bun. Keeps a pinned copy of the backend's `openapi.yaml` and generates its API client from it. Part of the Sorzs umbrella; cross-repo rules and decisions live in the umbrella's `CLAUDE.md` and `.claude/decisions.md`.

## Commands

- `bun run dev`: `dev.ts`, dev server on port 5173 (`PORT`) proxying the routes listed in `dev.ts` to `API_URL` (default `http://localhost:3000`) and serving `index.html` on any other path
- `bun run test`: `bun test`, with happy-dom and Testing Library preloaded from `test/setup.ts`
- `bun run lint`: Biome check (lint and format); `bunx biome check --write .` fixes
- `bun run typecheck`: `tsc --noEmit`
- `bun run build`: `build.ts` runs `Bun.build` on `index.html` into `dist/`; the `bun build` CLI ignores plugins, so Tailwind only works through this script
- `bun run generate`: `openapi-typescript` writes `src/api/schema.d.ts` from the pinned `openapi.yaml`
- `bun run generate:check`: fails when `src/api/schema.d.ts` differs from what `generate` would write

`openapi.yaml` is a copy of the backend's; refresh it by copying, then run `generate`. Never edit the schema by hand.

A change is done when test, lint, typecheck, build and generate:check pass.

## Image

`Dockerfile` installs production dependencies and runs `bun run dev` on port 5173 (`PORT`), with `API_URL` defaulting to `http://backend:3000`; `Sorzs-e2e` builds it. `docker build -t sorzs-frontend .`. In this sandbox bridge networking fails: build with `--network host` and run with `--network host`.

## Stack

Bun builds, serves and runs tests; no Vite, no Vitest. React, Tailwind v4 and shadcn on top. TypeScript stays on 5.x: `openapi-typescript` needs its JavaScript API, which 7.x lacks. Add no dependency without asking.

## Layout

`test/` mirrors `src/`. Fakes and builders that two or more tests share live in `test/support/`, the one folder with no counterpart in `src/`. Tests assert on public behavior, through Testing Library queries by role. A component that only composes others (`App`) is tested at its first level: that its direct child renders. The child's content belongs to the child's own test. `src/components/ui/` is generated by shadcn and excluded from Biome. Import with `@/` for `src/`.

Visibility driven by CSS variants (collapsed sidebar, breakpoints) cannot be asserted in happy-dom: a unit test only proves the element is in the DOM. Cover the visible state in an e2e spec.

`userEvent.upload` drops files whose type does not match the input's `accept`. Build test files with a type (`{ type: "image/jpeg" }`); without one the change handler never fires.

A test that asserts before a component's mount fetch settles leaves a pending update and an `act` warning. Either await the settled state, or give the test a `fetch` that never answers (`new Promise(() => {})`).

After `shadcn add`, search `src/components/ui/` for `from "cn"`: the generator writes that import and adds a `cn` dependency. Point the import at `@/lib/utils`, drop `cn` from `package.json` and run `bun install` so `bun.lock` drops it too.

`shadcn add sidebar` writes `--sidebar-*` colors in `hsl`, a `.dark` block and `@custom-variant dark` into `src/index.css`. Point each `--sidebar-*` at its Flexoki token (`--sidebar: var(--card)`) and delete the `.dark` block and the variant: the theme follows `prefers-color-scheme`, so they never apply.

`shadcn add` stops at a prompt when a dependency is already installed (`field` rewrites `label.tsx`). Run it with `--yes --overwrite`, then repeat the `from "cn"` fix.

A component does one thing: when its markup holds a second one (a trigger and its dialog, a row and its card), give that part its own component beside it in the same folder. The parent keeps the state and composes the parts, each part gets its content through props, and a rule-carrying callback is a named function in the parent. Tests stay on the parent until a part earns its own behavior.

Biome fails any function in `src/` over 60 lines (`noExcessiveLinesPerFunction`; `test/` is exempt). A component past it gives its markup parts their own components; one whose state and handlers fill the limit moves them to a `use<Name>` hook beside it (`useAddSourceForm`), leaving the component as markup. Never raise `maxLines` to pass.

A class that serves as an `openapi-fetch` middleware declares `onRequest` and `onResponse` as properties and does not `implements Middleware`: that type is a union and `tsc` rejects it (TS2422).

Type a form's `onSubmit` handler with `SubmitEvent` imported from `react`; the global DOM `SubmitEvent` fails `tsc`. `FormEvent` is deprecated in `@types/react` 19, and neither `tsc` nor Biome flags it.

A step that removes a method lists what else that method did (saving, navigating, notifying) and keeps a test for each effect that must survive.

A value a component hard-codes in a Tailwind arbitrary class (`text-[1.25em]`) becomes a token in `@theme` of `src/index.css` (`--text-wordmark`, used as `text-wordmark`), so changing it is one edit. Name the token for what it is. Never use `@apply` for a custom class: the component is the unit of reuse.

## Skills

Before writing or changing a component, read `.claude/skills/shadcn/SKILL.md` and `.claude/skills/vercel-react-best-practices/SKILL.md`; from a session started outside `frontend/` the Skill tool cannot load them. Check `src/components/ui/` and run `bunx --bun shadcn@latest add <component>` before styling markup by hand.
